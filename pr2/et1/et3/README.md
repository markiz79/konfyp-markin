# Вариант 15. Этап 3

Консольное приложение строит граф зависимостей пакетов Python обходом BFS
без рекурсии. Настройки читаются из TOML. Поддерживаются JSON API PyPI
и тестовый репозиторий. Используется только стандартная библиотека Python.

Пакеты добавляются в очередь один раз. Циклические связи сохраняются,
повторная обработка пакетов не выполняется. Глубина исходного пакета — 0.
Пакеты на максимальной глубине включаются в граф, но не запрашиваются.
Результат выводится списком смежности. Изображение пока не создаётся.

## Настройки

Все поля обязательны, без секции TOML.

| Поле | Значение |
| --- | --- |
| `package` | Имя исходного пакета. В тестовом режиме — заглавные латинские буквы. |
| `repository` | Базовый URL JSON API PyPI или путь к тестовому файлу относительно TOML. |
| `test_mode` | `true` для тестового файла, `false` для репозитория HTTP(S). |
| `output` | Имя PNG-файла без пути; на этом этапе только проверяется. |
| `max_depth` | Целое неотрицательное число: максимальная глубина BFS. |

Запрос к сети: `<repository>/pypi/<package>/json`.
Из `info.requires_dist` извлекаются имена всех объявленных зависимостей,
включая условные и дополнительные. Имена приводятся к нижнему регистру,
последовательности `.`, `_`, `-` заменяются на `-`.
Условия среды и extras не вычисляются, ограничения версий не разрешаются:
граф показывает объявленные связи последних версий из JSON API,
а не результат установки pip. Обычный индекс `/simple` не поддерживается.

## Функции

- `check_text` — проверка строковых настроек.
- `check_repository` — проверка адреса или доступности тестового файла.
- `check_url` — проверка HTTP(S)-адреса.
- `check_output` — проверка имени PNG-файла.
- `check_types` — проверка типов и диапазона глубины.
- `validate_config` — проверка состава и значений конфигурации.
- `load_config` — чтение TOML и проверка настроек.
- `extract_dependencies` — извлечение записей `requires_dist` из JSON.
- `get_dependencies` — запрос метаданных и обработка сетевых ошибок.
- `parse_test_line` — разбор строки тестового репозитория.
- `read_test_repository` — чтение графа, проверка имён и ссылок на пакеты.
- `normalize_package` — нормализация имени пакета Python.
- `dependency_names` — извлечение уникальных имён из записей зависимостей.
- `build_graph` — BFS с очередью, ограничением глубины и учётом посещений.
- `analyze` — выбор источника данных и построение графа.
- `get_neighbors` — получение соседей узла из сетевого репозитория.
- `print_graph` — вывод списка смежности и границы анализа.
- `main` — запуск приложения и обработка ошибок.

## Запуск и тестирование

Python 3.11 или новее. Сборка и сторонние библиотеки не требуются.
Команды выполняются из корня проекта.

Реальный репозиторий:

```sh
python src/main.py
```

Тестовый репозиторий:

```sh
python src/main.py examples/test.toml
```

Тесты:

```sh
python -m unittest discover -s tests -v
```

## Примеры использования

Формат `examples/repository.txt`: `ПАКЕТ: ЗАВИСИМОСТИ`.
Пакеты без зависимостей также описываются отдельной строкой.

```text
A: B C
B: D
C: D
D: A
E:
```

Конфигурация `examples/test.toml`:

```toml
package = "A"
repository = "repository.txt"
test_mode = true
output = "test_graph.png"
max_depth = 2
```

Результат:

```text
A: B, C
B: D
C: D
D: достигнута максимальная глубина
```

Для того же файла проверяются следующие случаи:

| Пакет и глубина | Результат |
| --- | --- |
| `A`, `0` | Только `A`, без чтения его зависимостей. |
| `A`, `1` | `A: B, C`; узлы `B` и `C` отмечены как граница глубины. |
| `A`, `3` | `A: B, C`; `B: D`; `C: D`; `D: A`. Цикл сохранён. |
| `E`, `3` | `E: нет зависимостей`. Остальные узлы недостижимы. |
| `Z`, `3` | Ошибка: пакет отсутствует в тестовом репозитории. |

Автоматические тесты также проверяют общую зависимость, петлю на себя,
повторяющиеся рёбра, кратчайшую глубину, длинную цепочку без рекурсии,
ошибки конфигурации, тестового файла, сети и JSON.
